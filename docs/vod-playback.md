# 点播连续播放与通用去广告

电影、电视剧的 HLS 播放统一通过 `src/lib/vod-playback.ts` 初始化。

- 保留源播放列表中的 `EXT-X-DISCONTINUITY` 和 `EXT-X-DISCONTINUITY-SEQUENCE`。这些标记用于衔接不同时间戳或编码参数的分段；删除后可能在每次分段切换时发生重叠、停顿或跳帧。
- 保留播放器“去广告”开关，默认开启，并兼容 `enable_blockad` 本地偏好。切换时重建视频缓冲并恢复当前进度，关闭后按原清单播放。
- 所有点播源共用同一个过滤入口，不按资源站名称或域名启停。`src/lib/vod-ad-detection.ts` 分析广告范围，`src/lib/vod-ad-rewrite.ts` 从完整点播清单中移除已确认的完整广告分片，将前后正片放在连续的播放时间轴上；不再用 GAP 留出广告空洞，也不再修改 `currentTime` 跨过广告。
- 被移除广告不计入播放器总时长，进度条不会在广告处突然前进几十秒。历史记录、片头片尾设置仍使用源时间轴保存，通过时间映射恢复到过滤后的正片位置；旧记录和去广告开关切换都使用同一映射。
- 支持完整的 `EXT-X-CUE-OUT / EXT-X-CUE-IN` 广告区间。仅有开始标签、嵌套标签、无效时长或零时长插入机会时，不把后续正片无限当成广告。
- 支持 `EXT-X-DATERANGE` 的 SCTE35 OUT/IN 配对，以及结合真实 `PROGRAM-DATE-TIME` 时钟和实际时长的广告范围。不会把提前公告的开始日期当成当前进度，也不使用仅供计划的 `PLANNED-DURATION` 猜测广告终点。普通章节等非广告日期标签继续保留。
- 支持 `com.apple.hls.interstitial` 独立插播资源：移除该插播事件的调度标签并关闭插播资产播放，保留全部主节目。不能将插播资产的时长直接从主节目中扣掉；例如 `X-RESUME-OFFSET=0` 表示插播后仍从原主节目位置继续。
- 对没有标准标记的源，保留已验证的 `/video/adjump/time/*.ts` 路径识别，并支持来自其他 CDN 的 `ad`、`ads`、`advertisement`、`preroll`、`midroll` 等明确目录。通用目录识别还要求短分片组、独立分段、与足够长的正片目录分离等上下文；整个正片目录碰巧叫 `ads` 不会整片删除。
- 对没有广告关键词的随机地址，只有完全相同的短分片组重复至少两次，且前后均为足够长、返回同一目录的正片时，才识别为重复插播。含加密、初始化映射或字节范围状态时，不启用此类重复推断。不同 CDN、短片长、文件名含 `ad` 或单个正常转场，均不单独作为判断依据。
- 只移除完整落在已识别广告范围内的分片；与广告部分重叠、还包含正片的分片完整保留，也不定时跳过其中的画面。保留正片 URI、实际分片时长、密钥及初始化映射；删片导致序号变化时，为 AES-128 补入原始序号对应的显式 IV，为隐式字节范围补入原始偏移量。广告后的时间戳边界保留或补入，连续的广告边界合并成一个；不删除普通正片的时间戳边界。同步转换 `EXT-X-START`，清理旧广告调度，避免清单重复处理误删正片。
- 主清单声明独立音轨或字幕资源时，暂不缩短各自时间轴，避免只删视频造成音画、字幕不同步；独立插播资产仍可禁用。低延迟分片、增量清单、未知加密方式或无法解析的偏移量保持原清单，不冒险拼接。分析失败时同样回退原清单。
- 用户提供的《现在就出发 第四季》20261017 第 2 期上，第一段已确认广告为 301.88–327.92 秒，共九个分片；同一清单在约 2427.48 秒还有一处同样的插入广告。规则依据实际分片路径识别，不硬编码片名或“五分钟”时间点。
- 该视频第一处广告前后的正片为 `0000099.ts` 和 `0000100.ts`，视频采样 PTS 分别结束于 303.343 秒、开始于 303.383 秒，源正片时间戳相接。旧版保留广告时长再跳转，造成约 27 秒的进度变化和缓冲空洞；新版完整保留这些正片分片，将总时长从 4701.08 秒缩短为 4649.00 秒。
- 关闭点播的低延迟模式，前向缓冲目标为 60 秒，最长目标为 120 秒，保留 30 秒后向缓冲。60 MB 是 hls.js 用来计算缓冲目标的字节参数，并非内存硬上限；实际下载量取决于码率、剩余片长和浏览器限制。播放器继续自动播放，不强制等待整个缓冲目标。
- 切集时先销毁旧 HLS 实例并清理时间映射。自动过滤使用 hls.js 的清单加载器；不支持 MSE 但支持原生 HLS 的浏览器继续原生播放，当前不提供该过滤能力，其缓冲由浏览器管理。

原版在全资源共用的自定义 HLS 加载器里，删除所有包含 `#EXT-X-DISCONTINUITY` 的行，也会连带删掉 `DISCONTINUITY-SEQUENCE`。它没有按源区分，也没有分析广告的实际开始和结束；广告文件本身仍在清单里。新实现沿用全资源共用的加载入口，保留正常时间轴边界，改为识别广告范围和独立插播调度。相同的旧代码也可在 [MoonTV 源码](https://github.com/samqin123/MoonTV/blob/main/src/app/play/page.tsx) 中看到。

标准标记依据 [AWS 的 HLS 广告标记文档](https://docs.aws.amazon.com/mediatailor/latest/ug/hls-ad-markers.html)，独立插播的主节目恢复语义依据 [Apple HLS Interstitials 文档](https://developer.apple.com/streaming/GettingStartedWithHLSInterstitials.pdf)。这些协议级规则不依赖某一个资源站。

测试覆盖多种清单结构、误判保护、时间映射、隐式字节偏移，并使用真实 hls.js 解析器检查拼接后的时长、片序、AES IV 和开关状态。浏览器验证使用公开测试视频构造不同的资源封装结构，并保留用户提供的暴风真实视频回归，检查广告请求、接点附近的等待缓冲和额外 seek；样例格式通过不代表已验证所有第三方资源站。没有可辨识特征的未知广告、烧录进正片的画面广告，仍不能保证自动去除。网络速度长期低于视频码率时，仍需切换到更快的播放源。
