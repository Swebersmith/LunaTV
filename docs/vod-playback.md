# 点播播放与广告分片过滤

## 独立播放器、投屏和触屏手势

Crayon Player 项目为 [Swebersmith/CrayonPlayer](https://github.com/Swebersmith/CrayonPlayer)。网站通过 `src/lib/crayon-player.ts` 使用 `packages/crayon-player/src/core.ts`，与独立播放器共用同一初始化入口，保留现有去广告、观看记录、片头片尾、选集和巨量切换逻辑。独立项目更新后运行 `node scripts/sync-crayon-player.mjs` 同步源码。

- 画面三等分：双击左侧快退 10 秒、中间暂停/继续、右侧快进 10 秒；长按 500ms 临时至少 2 倍速，松手恢复原倍速。横向滑动进度继续可用，单击显隐控制栏。
- 右侧上下滑动音量；设置 → 音量提供手动滑块；锁屏不响应手势。控制按钮和进度条不接管，切源、取消触摸、双指、失焦会取消加速。
- 关闭 ArtPlayer 自带 `fastForward` 和 `gesture`，避免重复处理。桌面鼠标和系统全屏行为沿用原播放器；系统原生视频全屏无法提供网页触屏操作，可用网页全屏。
- 控制栏新增「投屏」菜单，提供 AirPlay/系统远程播放和 Google Cast。官方 SDK 预加载，真实点击时直接打开选择器；Google Cast 发送原始媒体地址及换算后的原片时间，成功载入后才暂停本地。换源或销毁时使未完成的旧请求失效。
- 投屏依赖设备、浏览器、同一网络和电视访问原始片源的能力，不支持需要发送端 Cookie/Referer 的所有片源，也不保证兼容全部 DLNA 电视。开启去广告时，电视读取服务端过滤后的签名清单，并使用过滤后时间轴；片头片尾自动跳过仍只在本地执行；Google Cast 控制/停止使用其原生界面，电视进度和自动下一集不与本站联动。
- 已移除亮度调节。首次触屏播放展示三分区提示；单击收起控制栏时同步收起设置，播放中的设置面板也按交互闲置时间收起。限制程序音量的浏览器显示使用设备音量键的提示。

独立包包含可运行演示、类型声明、许可归属与自动检查。现有播放逻辑回归测试继续保留，真实电视连接需要设备验证。

## 播放器选择与巨量接入

播放页上方可选择Crayon Player 或巨量播放器；播放器、主/备用入口与智能匹配偏好保存在当前浏览器。默认使用Crayon Player。巨量完整 `/s/…`、`/parse` 页面地址会直接嵌入，不再进行二次解析。

按[巨量官方文档](https://juliang.app/docs/player)接入：

- 主入口 `https://jimaoys99.com/parse?url=`，备用 `jimaoys97.com`、`jimaoys95.com`，只改变播放器域名。
- 使用 `URLSearchParams` 编码一次，完整保留原片源签名、查询参数及已有的百分号编码。
- iframe 允许 `autoplay; fullscreen; picture-in-picture` 和 `allowFullScreen`，按官方要求不添加 sandbox。播放区有固定高度，本站的加载蒙层不覆盖巨量播放器。
- 可关闭智能匹配（播放器链接增加 `match=0`），避免第三方自动换线。集数和片源改变时卸载旧 iframe，再载入当前地址。
- 巨量「设置 → 广告屏蔽」自行管理智能识别、手动圈选、误遮撤销与遮蔽效果；本站不注入第三方脚本、不使用未公开参数修改其偏好。
- iPhone 系统视频全屏不显示网页遮挡层，片段过滤仍由巨量处理；可用「独立打开」进入巨量网页播放器。
- 广告识别可能遗漏或误判，匹配选线也取决于第三方片库，不能保证任何片源都去净广告。跨域 iframe 没有公开进度消息接口，巨量进度与本站观看记录、片头片尾配置不互通。
- 切换到巨量前保存内置进度、销毁 HLS/ArtPlayer、清除待执行的自动下一集与音量恢复定时器。返回相同地址时恢复内置进度；换集/换源后不套用旧进度。第三方过滤后可能改变时长，不混用两个播放器的时间轴。

验证：播放器集成测试覆盖切换资源释放、进度恢复、偏好恢复、选集重建、备用入口、全屏权限、完整播放页、无覆盖蒙层和慢入口提示；URL 测试覆盖签名参数、重复编码和非法协议。原版 HLS 去广告回归测试继续保留。iframe 的 load 事件只表示播放页载入，不视为视频已出画面或广告已被识别。

## Crayon Player的广告分片过滤

点播 HLS 由 src/lib/vod-playback.ts 初始化。Crayon Player「设置 → 去广告」默认开启，沿用 enable_blockad 偏好。当前实现按用户最新要求升级为实际的分片识别与移除，替代此前仅删除不连续标签的行为。

- 本地规则参考巨量当前播放器的分组思路：按 EXT-X-DISCONTINUITY 分组，综合主体路径、主流分片时长、重复插播指纹、短片段组合和帧率节奏判断。对合并后的删除结果统一限制：最多 5 组、不超过总时长的 10%，不足 120 秒的内容不自动删段。保守限制用于降低误删风险，不等同于巨量所有规则的完整复刻。
- 暴风的明确广告目录 `/video/adjump/time/` 按整组 URI 识别，兼容绝对地址、查询参数和 URL 编码；不依赖正片出现某个固定分片时长的比例，也不受通用重复指纹规则的 8 片上限限制。仍要求整个不连续组均为该广告路径、时长不超过 60 秒，并通过全局删除预算，混入正片 URI 时不删整组。
- 命中时移除整组广告 URI 和 EXTINF，保留正片真实的不连续边界；未命中时原清单逐字保留，不再无条件移除 DISCONTINUITY 或 DISCONTINUITY-SEQUENCE。
- 保留分片查询参数、密钥轮换和显式 IV。对 AES-128 隐式 IV，按删除前的原始媒体序号补写显式 IV，避免删段后序号变化导致正片无法解密。按 RFC 8216 处理协议版本要求。
- 播放界面使用过滤后的时长。观看记录、待恢复进度、片头片尾配置以原片时间轴保存，开关过滤或重新进入时转换为当前播放时间，兼容旧记录；恢复点落在广告内时定位到其后的正片。
- 自定义加载器仅处理主 manifest/level 文本并保留传输元数据。带外置音轨/字幕的多轨主清单整组保留，避免只剪视频导致音画错位。滚动直播、LL-HLS、字节范围、fMP4 MAP、DRM、无法安全解析的清单保持原样。Safari 原生 HLS 回退通过服务端准备过滤清单，保留原片时间轴元数据；准备失败不静默回退原片，可手动重试或关闭去广告。
- 开关显示实际结果（例如「已过滤 12.5 秒」）、未命中或暂不支持状态。不开启外部脚本、AI 模型、共享规则或广告情报上报；识别在本站浏览器端完成。
- 规则可能漏判或误判，不能保证所有片源都去净广告；关闭开关可恢复原清单。画面文字/二维码遮挡继续由可选的巨量播放器提供，不属于内置分片过滤。
- 保留点播缓冲优化：非低延迟模式，前向 60 秒/上限 120 秒、后向 30 秒、60 MB 缓冲；切集释放旧 HLS 实例。

验证使用真实 hls.js 清单解析器，覆盖广告 URI/时长移除、保留正常不连续片段、AES-128 隐式与显式 IV、密钥轮换、重复指纹、错误输入、外置音轨保护、直播/复杂格式透传、进度换算及播放器开关/切换。浏览器另使用本地合成 HLS 样本验证：蓝色正片 72 秒 + 红色广告 12.52 秒 + 绿色正片 72 秒，含 AES-128 加密与未加密两种版本。

## 原生 HLS 与投屏的服务端过滤

`/api/player/prepare` 验证现有登录后准备点播清单，返回绑定具体资源、8 小时有效的 HMAC 签名链接。`/api/player/media` 单独验证签名及期限，支持电视无 Cookie 读取清单、分片和 AES 密钥，支持 CORS、Range 与二进制流式返回。该入口不开放任意未签名 URL，不转发网站 Cookie，逐次检查上游重定向的协议与公网地址；签发不写 KV/D1。多轨主清单保留整组时间轴，复杂 HLS 保守透传。

已复现用户提供的暴风《熊出没之神奇宝物2》（ID 164713）：前 3 集现有规则均命中约 26.04 秒广告。修复原生 HLS/投屏绕过本地过滤的路径，保存第 1 集清单作为回归样本，核对正片 URI 和顺序不变。真实电视硬件仍需对应设备验证。
