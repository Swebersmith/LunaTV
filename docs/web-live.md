# 网页直播

在管理面板的直播源设置中开启网页直播，添加可访问的 HTTP / HTTPS M3U 频道列表即可使用。账号配置和 Cloudflare 数据库绑定无需写入 GitHub。

在“管理面板 → 直播源配置 → 直播节目单源（EPG）”添加共用节目单：填写名称、节目单地址和可选的 UA、备注，支持 XMLTV（`.xml` / `.xml.gz`）与 DIYP 格式的 JSON 接口。DIYP 可直接填写 `/api/diyp/` 基础地址，频道和北京时间的当天日期自动补齐；已有 `ch`、`date` 查询参数会自动更新，其余参数保留。可编辑、删除、启停，并用上下箭头立即保存优先级。无需改 GitHub、数据库表或 Cloudflare 绑定；节目单配置随站点备份导出和恢复。

XMLTV 按频道的 `tvg-id` 匹配；DIYP 按频道名查询，自动去除常见画质后缀并统一 CCTV 名称，缺少 `tvg-id` 的频道也可使用。跨午夜的节目转换为带时区的完整时间，每逢北京时间日期变化会使旧缓存失效；接口返回的“暂未提供节目预告”占位信息不会当成真实节目。优先读取直播源单独填写的节目单，再按顺序从启用的共用源补充缺失频道，最后尝试 M3U 自带的节目单。播放页只解析当前频道需要的数据，内存缓存十分钟；编辑、禁用或调整节目单源优先级后，下一次查询会检查新配置。无数据或下载失败短暂缓存一分钟，下载和解析有时间与大小限制，不阻塞视频播放，也不写 KV / D1。

- 默认通过站内代理播放，兼容没有跨域响应头或只有 HTTP 地址的直播源。支持主播放列表、备用音轨、AES 密钥、初始化分片和字节范围请求，保留源地址中的签名参数。
- Cloudflare Workers 的普通 `fetch` 不支持直接访问 IP 地址。对于使用公网 IP 的频道，程序自动使用 Workers TCP 连接传输 HTTP，保留原始端口、Host、User-Agent、Range 和签名参数，流式解析分块响应；普通域名继续使用 `fetch`。连接随播放取消或数据结束而释放，拒绝私网和本地地址，无需在 GitHub 或 Cloudflare 中逐个添加 IP 的 DNS 配置。
- PWA 对直播接口和媒体代理使用 NetworkOnly，避免离线缓存返回过期的直播播放列表或视频分片。
- Workers + D1 的播放列表、分片、密钥和台标走轻量媒体入口，直接验证现有登录签名并只读取所选直播源的 UA；不经过 Next.js 渲染、中间件和 Node/Web 视频流转换，也不读取整份用户与站点配置。其他部署方式保留原有接口。每次读取都检查源开关，禁用立即生效，不新增数据库表、绑定或写入。
- 公网 IP 转发按缓冲区扫描 HTTP 行；带 Content-Length 的响应在解析头部后交给 Workers 原生 FixedLengthStream 传输并检查长度，避免每个 TCP 包都执行 JavaScript。分块响应将细碎视频合并为至多 64 KiB 的输出块。媒体按需传输并传播取消，不把完整视频放入内存。
- 播放器识别到 Cloudflare 1102 资源限制时停止自动重连和备用线路轮询，保留手动重连入口，避免平台故障期间持续放大请求。1102 与 KV 写入配额耗尽不同；免费 Workers 的单次 CPU 预算仍是平台约束，不能通过延长网络超时来绕过。
- 直播入口发生重定向时，通过同站代理的临时重定向保留最终播放列表地址，让后续刷新继续使用该后端，避免反复经过调度入口而切到另一套直播时间轴。保留签名参数、直播源身份和直连选项，取消已丢弃的上游响应；所有媒体仍经过原有鉴权。签名地址失效时有限地回到原入口重新解析，也可刷新频道地址或切换同台备用线路，不把账号配置写入代码。
- 支持 MSE 的浏览器使用 hls.js，不支持 MSE 但具备原生 HLS 能力的 Safari / iOS 等浏览器会回退到原生播放。MP4 使用浏览器原生播放；FLV、RTSP、UDP、RTP 和设备不支持的编码需要源端转换为兼容的 HLS，网站本身不做转码。
- 自动播放被浏览器拦截时显示“点击播放直播”。网络故障有有限次数重连，媒体错误尝试恢复；连接或画面长时间停滞会显示重试按钮，并保留频道列表。
- hls.js 播放以稳定性为先：增加前向缓冲和直播边缘的安全余量，开播时按源的播放列表长度积累缓冲，额外等待最多六秒；播放列表很短时自动降低预缓冲要求。放宽较慢视频分片的超时，避免十秒即中断有效下载；允许小的时间轴间隙恢复。实际可缓冲时长受源端播放列表、码率和内存限制，开播速度和实时性可能略有下降。Safari / iOS 原生 HLS 的内部缓冲由浏览器管理。
- hls.js 过滤直播列表中完全倒退或远超经过时间的异常分片序号，防止上游交替返回不同时间轴而污染已缓冲数据。异常列表先按有限重试策略重新获取；连续三次异常时重新建立播放器时间轴，九十秒内最多自动重建一次，再次异常会尝试同台备用线路。状态只保存在当前播放器内存中，不缓存视频、不写入 KV / D1；点播和主播放列表不受此过滤影响。
- 播放中短暂等待不会立即盖住画面，持续缓冲以小提示显示。九十秒内三次超过一点五秒的停顿会尝试同台备用线路，仍受三条线路上限限制；没有可用备用线路时继续保留当前播放。正常播放不会定时刷新播放器或强制跳转直播进度。
- “使用代理重试”可以在当前播放会话中绕过浏览器直连设置，处理源端跨域或网络问题。
- 个人设置中的“IPTV 视频浏览器直连”默认关闭。开启后，仅 HTTPS 视频分片直接由浏览器请求，播放列表、密钥和 HTTP 分片仍经站点代理；源站必须允许跨域，且浏览器不能附带管理员配置的自定义 UA。直连失败会自动回退到完整代理，无需一律安装跨域插件。
- 开启浏览器直连后出现网络错误，会自动回退到完整代理。当前线路最终失败时，优先尝试配置中该频道的其他地址，最多尝试三条不同线路，不切换到其他电视台；手动选台或刷新频道后重新计数。登录过期单独提示，不触发线路轮询。
- 频道列表在 Worker 内存中缓存五分钟，加载失败时可用“刷新频道”立即重新拉取，播放失败时也可用“刷新频道地址”更新过期地址并保留当前频道。节目单独立按需读取，失败不影响播放。频道浏览、播放、重连、节目单读取不会写入 KV 或 D1；收藏、管理员保存和显式刷新频道数仍按操作保存。
- 切换频道、切换直播源和离开页面都会清理旧播放器、网络恢复定时器和待处理请求。

验证包括播放器生命周期和失败恢复测试、真实 workerd 中的代理与 Range 响应，以及桌面和移动尺寸浏览器中的真实 HLS 视频解码与切台。原生 HLS 分支有自动化测试；Windows 测试环境不能代替实体 iPhone / Safari 的验证。

第三方源失效、地域 / IP 限制、上游鉴权或浏览器不支持的音视频编码仍会影响播放。遇到这些情况应更换可用频道源。

观看直播不会造成服务器硬件损伤。站点不转码、不保存直播视频，视频按流转发，不会随观看时长持续累积到内存；代理仍消耗 Workers 请求数、CPU 和并发连接，读取配置也消耗数据库读取额度。达到套餐限额可能导致播放或站点暂时不可用，付费套餐也可能产生用量费用。直播播放本身不写入 KV / D1，收藏等用户操作除外。不要把免费额度理解为无限制的视频分发服务。
